# Game Voice AI Analyzer

## 项目愿景

做一个面向游戏开黑和普通语音内容的 AI 录音分析工具，把一段语音录音转换成可浏览、可点击、可修正、可总结的资料。用户不需要手动拖进度条反复听，只要上传或录制音频，就能看到时间轴转写、自然语言 AI 总结，并能回到具体时间点复听验证。

## 产品定位

这是一个 Web 优先、分段近实时分析路线的语音 AI 工具。当前阶段先服务“录音后分析”和“分段近实时分析”，暂不做真正实时流式 ASR，也不做实时陪玩/实时指挥。

Web 版优先支持麦克风录制。系统声音、游戏内语音、Discord/语音软件混音等采集能力，后续留给桌面端、浏览器扩展、虚拟声卡或系统级音频采集方案。

## 目标用户

- 经常组队开黑、想复盘团队沟通质量的玩家。
- 战队、车队、陪练或教练，想从语音中定位关键决策与协作问题。
- 内容创作者，想从语音素材中快速找出高光片段。

## 技术栈

- Frontend: Next.js, TypeScript, Tailwind CSS。
- Backend: FastAPI, Python 3.11, SQLite。
- Storage: 本地文件系统，音频文件默认保存到 `storage/audio/`。
- Spec Workflow: OpenSpec，用 change 驱动需求、设计和任务拆解。

## 当前已完成能力

- 上传本地音频文件。
- 后端保存音频文件。
- 前端可以播放已上传音频。
- 阿里云 ASR 真实转写。
- 转写时间轴展示。
- 点击转写片段可以跳转播放。
- 真实 LLM AI 总结。

## 当前路线

完整路线见 [roadmap.md](./roadmap.md)。

近期规划分为五个阶段：

- 阶段 A：修正层，支持编辑转写文本、speaker/channel 重命名，以及 AI 总结过期提示。
- 阶段 B：浏览器录音，支持 Web 麦克风录音并复用现有上传接口。
- 阶段 C：自动分析，支持上传或录音完成后自动转写、自动总结和处理状态展示。
- 阶段 D：分段长录音，支持长录音会话自动切片、分段上传、分段 ASR 和分段总结。
- 阶段 E：整场总结，基于所有 chunks 生成整场总结并支持 Markdown/TXT 导出。

## 明确不做的功能

- 实时录音。
- 真正实时流式 ASR。
- 用户登录。
- 支付系统。
- 移动端 App。
- 自动监听用户麦克风。
- 复杂权限系统。
- Web 版直接采集系统声音或游戏内语音。

## 开发原则

- 规格先行：任何业务能力先通过 OpenSpec change 明确目标、边界、验收标准和任务列表。
- 小步交付：每个 change 只解决一个清晰能力，避免把上传、转写、总结、风格分析一次性做完。
- 前后端分离：前端负责交互和播放体验，后端负责文件保存、元数据和分析任务编排。
- 离线 MVP 优先：第一阶段只处理用户主动上传的本地文件，不引入实时音频流。
- 分段近实时优先：后续长录音使用“自动切片上传 + 分段 ASR + 分段总结”的路线，不直接进入真正实时流式 ASR。
- 本地隐私优先：默认使用本地存储和 SQLite，后续接入云服务前必须重新评估隐私与安全边界。
- 可点击时间轴优先：所有分析结果都应尽量关联到音频时间码，方便用户回听验证。
- 可测试验收：每个需求都要能通过 API、页面行为或数据状态进行明确验证。
- 稳定主链路优先：后续功能不得大规模重构现有“上传/保存 -> ASR -> 时间轴 -> AI 总结”主链路；新增能力应尽量通过可组合的 change 叠加。
