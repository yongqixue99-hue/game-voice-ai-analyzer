# 项目路线图

## 当前进度

截至目前，项目已经完成以下主链路能力：

1. 音频上传与播放。
2. 阿里云 ASR 真实转写。
3. 转写时间轴展示与点击跳转。
4. 真实 LLM AI 总结。

这些能力构成当前稳定主链路：

```text
上传/录音音频 -> 后端保存 -> ASR 转写 -> 时间轴播放 -> AI 总结
```

后续功能应围绕这条主链路渐进扩展，不要为了新阶段大规模重构已有上传、ASR、时间轴和总结逻辑。

## 路线原则

- 暂不做真正实时流式 ASR。
- 当前采用“分段近实时分析”路线：把较长录音拆成多个可处理片段，每段独立上传、转写、总结，再汇总为整场总结。
- Web 版优先录制麦克风。
- 系统声音、游戏内语音、Discord/语音软件混音等采集能力，留到后续桌面端、浏览器扩展、虚拟声卡或系统级音频采集方案。
- 所有新能力继续通过 OpenSpec change 驱动，先写规格，再实现代码。
- 保持现有上传、ASR、总结主链路稳定，新增功能优先复用现有接口和数据结构。

## 阶段 A：修正层

Change：`transcript-editing-speaker-labels`

目标：让用户可以修正 ASR 结果，并确保 AI 总结基于用户修正后的转写生成。

范围：

- 支持编辑 transcript segment 文本。
- 支持 Channel/Speaker 重命名，例如把 `Channel 0` 改为“主持人”“嘉宾”“我”“队友 A”。
- 修改转写文本或 speaker label 后，已有 AI 总结提示可能过期。
- 重新生成 AI 总结时使用最新转写文本和 speaker display name。

不做：

- 不做说话人分离算法。
- 不自动识别谁是谁。
- 不做复杂版本管理或多人协作编辑。

## 阶段 B：浏览器录音

Change：`browser-recording-basic`

目标：让用户不必先准备本地音频文件，可以直接在 Web 页面录制麦克风音频。

范围：

- 前端支持开始录音。
- 支持暂停/继续。
- 支持停止录音。
- 停止后生成音频文件。
- 录音文件复用现有上传接口保存。
- 上传成功后可以自动触发 ASR 和 AI 总结。

技术路线：

- 优先使用浏览器 `MediaRecorder` 录制麦克风。
- 录音结束后生成 `Blob/File`，走现有 `POST /api/recordings/upload`。
- 不新增独立录音存储链路，避免绕开现有上传/保存能力。

不做：

- 不采集系统声音。
- 不采集游戏内语音。
- 不做真正实时 ASR。

## 阶段 C：自动分析

Change：`auto-transcribe-and-summary`

目标：减少用户手动点击步骤，让上传或录音完成后可以自动执行转写和总结。

范围：

- 上传完成后可选择自动转写。
- 转写完成后可选择自动总结。
- 浏览器录音完成上传后可复用同一自动分析流程。
- 前端显示处理状态：
  - 上传中
  - 转写中
  - 总结中
  - 完成
  - 失败

技术路线：

- 优先在现有前端流程中编排已有 API。
- 后端可保留同步接口，必要时再增加轻量任务状态字段。
- 不引入复杂队列系统，除非长任务稳定性成为阻塞问题。

不做：

- 不做后台分布式任务系统。
- 不做多用户任务队列。
- 不做复杂重试策略。

## 阶段 D：分段长录音

Change：`recording-session-auto-chunking`

目标：支持长时间录音，并通过自动切片实现接近实时的分段分析体验。

范围：

- 支持开始长录音会话。
- 每 3-5 分钟自动切片上传一个 chunk。
- 每个 chunk 自动 ASR。
- 每个 chunk 自动生成分段总结。
- 页面展示每段状态和分段总结。

技术路线：

- 新增 recording session 概念。
- chunk 继续复用现有上传/保存/ASR/总结主链路。
- 每个 chunk 作为可独立播放、转写、总结的 recording 或 recording-like 子资源。
- 页面按时间顺序展示 chunks。

不做：

- 不做真正实时流式 ASR。
- 不做低延迟逐字字幕。
- 不做系统声音或游戏内语音采集。

## 阶段 E：整场总结

Change：`session-level-summary`

目标：在长录音分段分析完成后，基于所有 chunks 生成整场级别总结。

范围：

- 汇总所有 chunks 的转写文本。
- 汇总所有 chunks 的分段总结。
- 生成整场总结。
- 支持导出 Markdown。
- 支持导出 TXT。

输出内容：

- 整场一句话标题。
- 整体摘要。
- 时间顺序大纲。
- 关键结论或重点信息。
- 待确认信息或识别不确定点。

不做：

- 不做复杂报告模板系统。
- 不做 PDF/视频导出。
- 不做自动剪辑或高光视频生成。

## 后续待评估方向

- 桌面端采集系统声音或游戏语音。
- 虚拟声卡接入方案。
- 说话人分离或说话人聚类。
- 长音频异步任务队列。
- 更完整的导出格式。
- 多项目/多用户管理。
