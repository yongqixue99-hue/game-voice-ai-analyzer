# 音频上传与播放

## Goal（目标）

实现第一条离线音频 MVP 闭环：上传本地游戏语音录音，后端保存文件，展示已保存录音，并在网页中播放选中的录音。

## User Story（用户故事）

作为一个复盘已结束游戏对局的玩家，我希望上传本地语音录音并在网页中回放，这样后续的转写和 AI 复盘能力可以挂载到同一条已保存录音上。

## API Design（API 设计）

- `POST /api/recordings`
  - 请求：`multipart/form-data`，必填 `file` 字段，可选 `display_name`。
  - 响应 `201`：录音元数据 JSON。
  - 校验：拒绝缺失文件、空文件、不支持的非音频文件，以及超过配置大小上限的文件。
- `GET /api/recordings`
  - 响应 `200`：录音元数据 JSON 列表，按最新上传优先排序。
- `GET /api/recordings/{recording_id}`
  - 响应 `200`：单条录音元数据 JSON。
  - 响应 `404`：录音不存在。
- `GET /api/recordings/{recording_id}/audio`
  - 响应 `200`：带保存内容类型的可播放音频响应。
  - 响应 `404`：录音元数据或已保存文件不存在。

## Data Model（数据模型）

SQLite 表：`recordings`

- `id`：字符串 UUID 主键。
- `original_filename`：用于展示的原始上传文件名。
- `display_name`：可选的用户可见名称。
- `stored_filename`：服务端生成的安全磁盘文件名。
- `content_type`：上传音频的 MIME type。
- `size_bytes`：上传文件大小，单位字节。
- `duration_seconds`：可为空的音频时长字段，预留给未来元数据提取。
- `storage_path`：已保存文件的后端本地路径或相对路径。
- `created_at`：上传时间戳。

## ADDED Requirements

以下为本变更新增需求。

### Requirement: 上传本地音频文件

系统 SHALL 允许用户从前端上传本地音频文件到后端。

#### Scenario: 有效上传

- **WHEN** 用户选择受支持的音频文件并提交上传表单
- **THEN** 后端保存音频文件，并返回包含唯一录音 ID 的录音元数据

#### Scenario: 无效上传

- **WHEN** 用户没有提交文件、提交空文件、提交不支持的非音频文件，或提交超过配置大小上限的文件
- **THEN** 后端以校验错误拒绝请求，并且不创建录音

### Requirement: 持久化上传音频文件

系统 SHALL 将每个通过校验的上传音频文件保存到后端控制的本地存储中，并且不能信任原始文件名作为存储路径。

#### Scenario: 文件被安全保存

- **WHEN** 上传音频文件通过校验
- **THEN** 已保存文件使用生成的安全文件名，并位于 `storage/audio/` 下

### Requirement: 持久化录音元数据

系统 SHALL 将每条通过校验的录音元数据持久化到 SQLite。

#### Scenario: 元数据行被创建

- **WHEN** 上传音频文件被保存
- **THEN** SQLite 中存在一条录音记录，包含 ID、原始文件名、存储文件名、内容类型、文件大小、存储路径和创建时间戳

### Requirement: 列出录音

系统 SHALL 为已上传录音提供录音列表 API 和前端列表视图。

#### Scenario: 已上传录音出现在列表中

- **WHEN** 一条录音上传成功
- **THEN** 录音列表包含该录音及其展示元数据

#### Scenario: 没有录音

- **WHEN** 尚未上传任何录音
- **THEN** 前端展示空状态，而不是错误状态

### Requirement: 在浏览器中播放已保存录音

系统 SHALL 允许用户在前端通过后端音频端点播放已保存录音。

#### Scenario: 选择录音进行播放

- **WHEN** 用户从录音列表中选择一条录音
- **THEN** 前端将该录音的音频 URL 加载到浏览器音频播放器中

#### Scenario: 录音音频缺失

- **WHEN** 选中录音的元数据或已保存文件不存在
- **THEN** 后端返回 `404`，前端展示可恢复的错误状态

## Acceptance Criteria（验收标准）

- 用户可以从前端上传受支持的音频文件。
- 上传文件使用生成的安全文件名保存到 `storage/audio/` 下。
- 每次成功上传都会创建一条 SQLite 元数据记录。
- 上传成功后，录音列表不需要刷新页面即可展示新录音。
- 选择一条录音会将其加载到 HTML audio 播放器中。
- 刷新页面后，仍然可以从 SQLite 中看到之前上传的录音。
- 无效上传不会创建已保存文件或元数据记录。

## Out of Scope（不在范围内）

- 实时录音。
- 实时语音识别。
- 转写时间轴生成。
- 点击转写片段跳转播放。
- AI 总结生成。
- 高光片段检测。
- 玩家沟通风格分析。
- 用户登录。
- 支付系统。
- 移动端 App。
- 自动监听麦克风。
- 复杂权限系统。
- 云存储。
