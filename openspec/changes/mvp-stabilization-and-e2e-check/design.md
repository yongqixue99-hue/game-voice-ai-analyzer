## Context

MVP 当前能力包括：

- 音频上传与播放。
- 阿里云 ASR 真实转写。
- 转写时间轴展示与点击跳转。
- 真实 LLM AI 总结。
- 转写文本编辑和 Channel/Speaker 重命名。
- 浏览器单段录音。
- 上传/录音完成后自动 ASR + 自动 AI 总结。
- 分段长录音 session/chunk。
- session-level-summary 整场总结和 Markdown/TXT 导出。

阶段 F 只做稳定化，不引入桌面端、系统声音录制、FunASR 本地部署、实时流式 ASR 或复杂 UI 重设计。

## Decisions

### 1. 优先修复当前可检测问题

优先级：

1. 前端 TypeScript/build/lint 失败。
2. 后端测试失败。
3. 明显无限 loading、未捕获异常、半接入功能未挂载。
4. 错误状态不可读或缺少重试入口。
5. 文档缺失。

### 2. 保持主链路不重构

不会替换现有上传、ASR、AI 总结、录音和 session/chunk API。若发现问题，以局部修复为主。

### 3. 不伪造手动验收结论

麦克风权限、真实浏览器录音、ngrok/公网地址、阿里云 ASR、真实 LLM 调用等依赖本机和云端环境的项目，自动化无法完全确认时，写入手动验收清单，不宣称已人工通过。

### 4. 文档作为阶段 F 交付物

新增 `docs/manual-e2e-test.md`，覆盖：

- 环境变量配置。
- 后端/前端启动。
- PUBLIC_BASE_URL 暴露方式。
- 上传音频、浏览器录音、长录音、整场总结和导出流程。
- 常见问题排查。

## Risks / Trade-offs

- 真实 ASR/LLM 链路依赖密钥、公网 URL 和外部服务状态，自动测试只能覆盖错误处理和 mock/provider 结构。
- 浏览器录音需要用户授权麦克风，命令行测试无法替代实际点击。
- 长录音 30 秒以上分段测试耗时，阶段 F 只做代码和文档加固，最终体验仍需手动确认。
